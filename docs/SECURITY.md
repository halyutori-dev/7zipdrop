### ライセンス遵守

7-Zip の FAQ が定めるバイナリ再配布条件は3つで、いずれも満たしています。

1. 7-Zip コンポーネントを使用している旨の明記 → `NOTICE.md`、アプリの「同梱している 7-Zip について…」メニュー、Info.plist の著作権表記
2. GNU LGPL であることの明記 → 同上 + `Contents/Resources/ThirdParty/7-Zip/License.txt` に全文同梱
3. www.7-zip.org へのリンク → 同上

LGPL の派生物条項について: 本アプリは 7zz を**リンクせず、独立したプロセスとして exec** しています。
7zz は無改変で、対応するソースは配布元で公開されています。

  `scripts/fetch-7zz.sh` のバージョンと SHA-256 を上げて `make app` するだけで差し替えられる
  形にしてあります（監査がハッシュの一致を毎回検査します）。
- 自動判別で展開するのは、利用者が「書庫」と思う拡張子だけです。`exe` / `dmg` / `iso` /

- 展開は常に**空の一時ディレクトリ**に対して行い、成功して検査を通ったものだけを移動します。
  7zz が誤動作しても、利用者の既存ファイルは射程に入りません。

## 2.5 展開側の多層防御

7-Zip 26.02 自身も Zip Slip を無害化しますが（契約 #26/#27 で実測）、**exit 0 のまま黙って
パスを書き換える**ため「防げた」ことも「何が起きたか」も利用者に見えません。そこで 7-Zip の
挙動に依存しない独立した検査を入れています。

| 脅威 | 対策 | 実測での裏付け |
|---|---|---|
| Zip Slip（`../` による展開先外への書き込み） | 展開前に listing の全 entry パスを検査し、**安全な形の allowlist** に合わないものがあれば既定で拒否（`allowUnsafeEntryPaths`、既定 off） | 自作の悪意ある zip を fixture 化してテスト（`slip-rel.zip`） |
| 絶対パス entry（`/etc/passwd` 等） | 同上（先頭 `/` を持つ entry を拒否） | `slip-abs.zip` |
| symlink 経由の脱出（リンクを作ってその先へ書く） | listing にリンク先が出ないため（契約 #30）、**展開後に実ファイルシステムを走査**し、staging の外を指す symlink が 1 つでもあれば結果を破棄。走査は symlink を辿らない | `slip-link.zip` |
| zip bomb（少量の書庫が巨大に展開される） | listing の申告サイズ合計を、**設定した上限**と**実際の空き容量（1 GiB の余裕込み）**の両方で fail-closed 判定。申告は Int64.max に飽和させて読む（巨大申告でも溢れて落ちない・0 にならない） | 7,831 バイト → 50 MiB を申告する書庫で実測。2^64 近い申告の zip64 を自作して実測（契約 #42） |
| 申告の無い / 信用できない展開サイズ（bz2・zst・lzma・Z は申告なし、gzip は 2^32 の剰余） | 事前検査では上限を付けられないため、**展開中に実書込み量を 100 ms ごと（と終了後にもう一度）測り**、上限か空き容量を超えた時点で 7zz を SIGTERM で止めて結果を破棄。形式の判定は拡張子ではなく 7zz が内容から出す `Type` も使う | 178 バイト → 200 MB の bzip2、ISIZE を書き換えた gzip を fixture 化してテスト（契約 #42） |
| 既存ファイルの上書き | `-aos` と空 staging への展開、最終配送は `renamex_np(RENAME_EXCL)` による**アトミックな名前取得** | 2 回展開して 1 個目が編集ごと保持されることをテスト |
| 対話プロンプトでの停止 | `-aos` によりプロンプトが発生しない（プロンプトは非 tty で exit 255 になる、契約 #25） | 実測 |
| 元の書庫の破壊 | 展開処理は書庫を一切書き換えず・削除しません（監査が `removeItem` の対象を検査） | テストで書庫のバイト列不変を確認 |

**この防御は意図的に少し過剰です**: `a/b/../c.txt` のように実際には脱出しない `..` も拒否します。
「どの traversal が無害か」を判定する代わりに「正しい形だけを通す」ことで、判定漏れが起きない側に
倒しています。信頼できる書庫だと分かっている場合は詳細設定で明示的に許可できます。

## 2.6 「展開先の外を指すパスを含む書庫も展開する」について（設定から外した理由）

この設定は **UI から外しました**（コードには残していますが、既定 `false` のままで UI からは
変更できません）。有効にする正当なケースが見つからなかったためです。

書庫のエントリパスが `../` や絶対パスになるのは、実際には次のどちらかです。

1. **攻撃**（Zip Slip）。展開先の外にファイルを書かせるのが目的です。
2. **絶対パスを保存する古いツールで作られた書庫**（`tar -P` など）。この場合も、
   一度どこかに展開してから手で移動すれば済むので、危険なパスをそのまま通す必要はありません。

以前「正当なケースかもしれない」と考えていた `./` 付きエントリ（素の `tar cf x.tar .` が作る形）は、
**調べたところこちらの検査の不備でした**。`.` 成分は展開先の外へ出られないのに拒否していたため、
普通の tar が「危険な書庫」として開けませんでした（契約 #40）。これを修正した結果、
この設定を有効にすべき場面は残っていません。

なお、逃げ道自体をコードから消していないのは、ゲートが実際に効いていることを
テストで示す口（`allowsUnsafePathsOnlyWhenAsked`）として使っているためです。

## 2.7 破壊的になり得る新しい設定（v1.2）

| 設定 | 既定 | 破壊を避けるための作り |
|---|---|---|
| 圧縮後に元のファイルを削除 | **オフ** | 7-Zip の `-sdel`（完全削除）は使わず、`FileManager.trashItem` で**ゴミ箱へ移動**。書庫の配送が完了し、かつ 7-Zip が**警告なし**で終わったときだけ実行（警告は「一部のファイルが書庫に入っていない」の意なので、元ファイルが唯一の複製になり得る）。削除に失敗した項目は結果に件数を表示 |
| 展開時の同名ファイルの上書き | **オフ** | オフのときは `名前 2` のように空き名を使い既存に触りません。オンのときも、置き換えられる側を**ゴミ箱へ移動**してから配置します（`unlink` しません） |

`scripts/security-audit.sh` の #9b がこの 2 点（既定オフ・ゴミ箱経由・成功時のみ）を毎回検査します。

## 2.8 起動時にキーチェーンを読まない（v1.2 で修正した不具合）

初期の v1.2 実装は `AppModel.init()` で同期的にキーチェーンを読んでいました。ad-hoc 署名は
**再ビルドごとに変わる**ため、securityd がアクセス承認を待ち、**ウインドウが出る前にアプリが
永久にハング**しました（`sample` で `SecItemCopyMatching` → `decrypt` → `mach_msg` で停止しているのを確認）。

対策として、
- 起動時にキーチェーンを読みません。「共通パスワードが設定済みか」は `UserDefaults` の
  **真偽値フラグ**で持ちます（パスワード本体は入れません）。
- キーチェーンの読み書きは必ず `Task.detached` の中で行い、メインスレッドを止めません。

`scripts/security-audit.sh` の #9c が「`init()` がキーチェーンに触れていないこと」と
「すべてのキーチェーン呼び出しが detached task の中にあること」を毎回検査します。

## 3. サプライチェーン

- Swift の外部パッケージ依存は **0 件**（Apple のフレームワーク + 同梱 7zz のみ）
- ネットワーク API を一切使用していません（`URLSession` 等の参照が 0 件であることを監査で検査）
- ビルド時にコードを取得する仕組みはありません（`fetch-7zz.sh` のみで、それは checksum 検証付き）

## 4. パスワードの取り扱い

| 経路 | 対策 |
|---|---|
| コマンドライン (`argv`) | 圧縮時は **`-p` を値なしで渡し、パスワードは標準入力**で渡します。`ps` などのプロセス一覧に出ません（契約 #1） |
| 検証時 (`7zz t`) | `t` は標準入力からパスワードを読めません（契約 #21）。そのため**既定では暗号化書庫の検証をスキップし、「検証スキップ」と表示**します。argv 露出を許容する場合のみ明示的にオプトインできます |
| 展開時 (`7zz x` / `l`) | `x` も `l` も標準入力からパスワードを読めません（契約 #24/#36。pipe・pty の両方で実測）。**暗号化書庫を展開するには argv 経由が唯一の手段**です。回避策が無いため、この点は隠さず文書と UI に明記しています。表示・ログでは常に `-p********` にマスクします |
| 画面表示・ログ | `-p<secret>` 形式の引数は常に `-p********` にマスク（`Password` 型の `description` も秘密を出しません） |
| 永続化 | `UserDefaults` / plist には**書きません**。ユーザーが明示的に有効化したときのみ Keychain に保存します |
| Keychain 属性 | `kSecAttrAccessibleWhenUnlocked`・iCloud 同期なし |
| 入力検証 | 改行・NUL を含むパスワードは受け付けません（標準入力経路が1行のため、黙って壊れるのを防ぐ） |
| 暗号強度 | 7z は AES-256。**zip は既定が ZipCrypto（実質破られる）なので `-mem=AES256` を強制** |

## 5. コマンド注入・引数注入

- 7zz は**シェルを経由せず**引数ベクタで直接 exec します（`/bin/sh`・`system()`・`popen()` の使用なし）。
  ファイル名に `;` や `$(...)` が含まれていても意味を持ちません。
- `--` を必ず付けるため、`-rf.txt` のような名前がスイッチとして解釈されることはありません。
- `-spd` を必ず付けるため、`report*.pdf` のような名前がワイルドカードとして展開され
  **意図しないファイルが書庫に混入すること**がありません。
- 子プロセスの環境変数は `LC_ALL` と `PATH` のみに絞っています。

## 6. ファイル破壊のリスク

- **既存ファイルを上書きしません。** 7zz は既存書庫に黙って追記する挙動（契約 #3）なので、
  空き名を選んだうえで最終確定は `link(2)` による**アトミックな名前取得**で行い、
  取られていたら上書きせず失敗します。
- 一時ディレクトリ（0700）で作成し、成功時だけ最終位置へ移動します。異常終了・強制終了でも
  保存先に中途半端なファイルが残りません。
- **元ファイルを削除する機能を持ちません**（7-Zip の `-sdel` を意図的に配線していません）。
  コード中に `-sdel` が現れないことを監査で検査します。
- 読み取れないファイルがあれば既定で**中止**します（`-sse`）。無効化した場合は
  「一部のファイルが入っていない可能性」を結果に明示します。

## 7. 署名 / 配布

- ローカルビルドは **ad-hoc 署名**（`codesign --verify --deep --strict` が通ることを監査で検査）。
- `LSHandlerRank = None`: Dock ドロップと「このアプリで開く」は受け付けますが、
  どのファイル形式の既定アプリにもなりません。
- App Sandbox は**有効化していません**。ドロップされた任意の場所のファイルを読み、
  その隣に書き込む必要があるためです。配布する場合は Developer ID 署名 + notarization、
  および（App Store 配布なら）sandbox + security-scoped bookmark の実装が別途必要です。

## 7.5 展開時の判断の分かれ目（記録）

- 暗号化書庫の展開に argv を使うのは、**7-Zip 側に他の受け渡し口が無い**ためです（pipe・pty の
  両方で実測して確認）。「隠して argv を使う」ことはせず、`docs/VERIFIED-7ZIP-CONTRACT.md` #24/#36 に
  実測根拠を残し、UI にも書いています。同一ユーザーのプロセスからは展開中だけパスワードが見えます。
- 「危険なパスを含む書庫も展開する」設定を用意していますが既定は off です。on にした場合も、
  何件のパスが書き換えられたかを結果に表示し、黙って通しません。
- 展開後の symlink 検査は、リンクを**辿らずに**ツリーを走査します。悪意あるリンクで走査自体を
  外へ誘導されないようにするためです。
